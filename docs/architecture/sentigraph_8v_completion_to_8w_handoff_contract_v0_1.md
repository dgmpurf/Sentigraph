# Sentigraph 8V Completion to 8W Handoff Contract v0.1

## A. Contract Purpose

This contract defines how the completed 8V local backend metadata boundary chain may hand off to a future 8W real exported package metadata selection phase.

The purpose is to preserve the distinction between:

- completed local metadata boundary markers in 8V
- a future docs-only decision about selecting real already-exported package metadata
- any later implementation, which must be separately approved

This contract is not runtime implementation. It is not private collector access. It is not evidence row parsing. It is not Evidence Layer import. It is not production case creation. It is not production `analysis_run` creation. It is not export/download/public access/final-delivery runtime. It is not route/frontend integration.

## B. 8V Completed Local Metadata Boundary Chain

The completed 8V local chain is:

1. provider result metadata
2. safe package resolver
3. local exchange metadata smoke
4. review-only staging candidate
5. staging candidate generated-run bridge
6. controlled minimum real-run bridge execution
7. `sentigraph_opinion_ecosystem_run_v0_1` generated run
8. controlled generated-run dense graph bridge integration
9. backend-only dense graph preview
10. `sentigraph_dense_graph_report_candidate_v0_1` local report candidate
11. `sentigraph_report_candidate_final_report_boundary_v0_1` local final-report-boundary object
12. `sentigraph_final_report_boundary_source11_governance_handoff_v0_1` local Source 11 governance handoff marker
13. `sentigraph_source11_governance_handoff_finalsummaryreport_adapter_v0_1` local FinalSummaryReport boundary adapter
14. local in-memory `sentigraph_final_summary_report_v1`-shaped boundary object
15. `sentigraph_finalsummaryreport_boundary_export_gate_handoff_v0_1` local export-gate handoff/readiness marker
16. `sentigraph_export_gate_handoff_export_artifact_boundary_v0_1` local export-artifact boundary/readiness marker
17. `sentigraph_export_artifact_boundary_download_public_access_boundary_v0_1` local download/public-access boundary/readiness marker
18. `sentigraph_download_public_access_boundary_final_delivery_boundary_v0_1` local final-delivery boundary/readiness marker

These objects are local backend helper/test-path metadata markers. They are not production records, public/customer outputs, or delivery artifacts.

## D. Future 8W-1 Docs-only Scope

Future 8W-1 should be a docs-only decision that defines how to select a real already-exported package metadata target for possible later controlled validation.

8W-1 may define:

- selection criteria for a real already-exported package metadata target
- safe package identity fields that may be referenced without private paths
- required metadata-only preflight checks
- package status requirements
- safety blockers
- no-row-read boundaries
- no-private-collector-inspection boundaries
- provider-output-is-evidence-not-truth boundary
- required exact approval phrase for any later implementation

8W-1 must not implement a selector, run a selector, read a real exchange directory, read private collector source, parse row files, call APIs, call LLMs, fetch URLs, scrape, write Evidence Layer, create production records, or create public/customer output.

## H. Future 8W Explicit Approval Protocol

Future 8W-1 is docs-only and needs no implementation approval.

Any later implementation must require exact approval language. The recommended phrase is:

`批准 8W-2 Controlled Real Exported Package Metadata Smoke implementation`

Without that exact or equivalent explicit approval, do not implement selectors, do not read real exchange directories, do not inspect private collector source, do not parse rows, do not create runtime objects, and do not touch Evidence Layer, production cases, production `analysis_run`, frontend, routes, B-end reports, Sandbox/public events, or final delivery surfaces.

Even with 8W-2 approval, the default implementation scope should remain metadata-only unless the user separately approves row reads or runtime behavior.

## I. Relationship to Source 11 and Private Collector

8V-25 and future 8W-1 do not modify Source 11 behavior.

Source 11 should not be updated unless actual Analysis Request / Provider / Import Governance / FinalSummaryReport / export/download/public-access/final-delivery governance behavior changes.

Private collector boundaries:

- do not inspect private collector source
- do not run collector
- do not read collector sessions, cookies, tokens, profiles, or secrets

- do not parse original package rows unless a later task explicitly approves that exact action

The 8W handoff may discuss real already-exported package metadata only as a future selection target, not as data that has been read in 8V-25.
