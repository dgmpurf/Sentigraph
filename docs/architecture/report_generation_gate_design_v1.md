# Report Generation Gate Design v1

## Purpose

Report Generation Gate defines the future governance gate between a `ManualAnalysisResultCandidate` and any Summary Report, B-end report, export package, Sandbox fixture, or public event page.

The gate exists because an analysis result candidate is not report-ready by default. It must prove that source scope, evidence review, deduplication, warnings, exclusions, and audit boundaries are preserved before any future report runtime can format the result for readers.

This document is design-only. It does not implement runtime and does not generate a report.

## Core Principle

A `ManualAnalysisResultCandidate` is not automatically report-ready.

A result candidate is not:

- a Summary Report
- a B-end report
- a PDF export
- a Markdown export
- a briefing deck
- a Sandbox fixture
- a public event page
- official verification
- full-web coverage
- full-platform coverage
- full-thread coverage

Report Generation Gate must preserve:

- reviewed evidence scope
- boundary block from the result candidate
- coverage limitation
- provider output is evidence, not truth
- rejected evidence exclusion
- weak evidence warnings
- duplicate evidence non-amplification
- privacy and needs-more-source exclusions
- audit traceability
- no official verification claim
- no full-web or full-platform claim

## Required Prior Chain

Report Generation Gate can only be considered after:

- Manual Analysis Execution exists.
- Manual Analysis Result Candidate exists.
- Manual Analysis Execution Audit exists.
- Analysis Result Boundary Gate exists.
- The candidate includes a boundary block.
- Rejected evidence is excluded.
- Weak evidence remains warning-marked.
- Duplicate evidence does not amplify risk, sentiment, coverage, or conclusions.
- Provider output is explicitly treated as evidence, not truth.
- The candidate does not claim official verification.
- The candidate does not claim full-web or full-platform coverage.
- No `privacy_hold` blockers exist.
- No unresolved `needs_more_source` blockers exist.

If any prior item is missing, unsafe, incomplete, or inconsistent, this gate must return `incomplete`, `blocked`, or `privacy_hold`.

## Future Statuses

### `report_gate_ready_for_future_runtime`

All required report-boundary inputs are present for a future Report Generation Gate runtime to evaluate.

This status still does not generate a Summary Report, B-end report, export file, Sandbox fixture, public event page, or production Evidence Layer record.

### `incomplete`

Required execution, candidate, boundary, warning, exclusion, dedup, coverage, or audit data is missing.

### `blocked`

Unsafe conditions are present, such as rejected evidence leakage, duplicate amplification risk, missing boundary block, missing coverage limitation, missing weak-evidence warning, overclaiming, attempted trust upgrade, or attempted output generation.

### `privacy_hold`

Privacy, private-content, raw-identifier, or secret-like risk is present. All downstream report, export, Sandbox, and public-event gates must stop until a separate privacy review resolves the issue.

## Boundary Checks For Future Runtime

A future runtime must verify:

- `ManualAnalysisResultCandidate` is the only report input source.
- The result candidate boundary block is present.
- Rejected evidence is excluded.
- Weak evidence remains warning-marked.
- Duplicate groups do not multiply risk, sentiment, coverage, or conclusions.
- Duplicate counts are context only.
- Provider output remains evidence, not truth.
- Coverage limitations are visible.
- Audit trace references are available.
- No official verification claim is made.
- No full-web coverage claim is made.
- No full-platform coverage claim is made.
- No Summary Report, B-end report, export file, Sandbox fixture, or public event page is generated by this gate.

## Required Reader-Facing Notes

Future report runtime, export metadata, and public-facing derivatives must preserve notes equivalent to:

- The report candidate is based on reviewed evidence scope, not all possible evidence.
- Provider output is evidence, not truth.
- This is not official verification.
- This is not full-web, full-platform, or full-thread coverage.
- Rejected evidence was excluded.
- Weak evidence remains warning-marked.
- Duplicate evidence must not amplify risk, sentiment, or conclusions.
- Audit trace is available for review, dedup, promotion, analysis, and boundary decisions.

## First Runtime Recommendation

Future 7I should:

- create a report gate record from a `ManualAnalysisResultCandidate`
- validate the candidate boundary block
- validate required warning sections before any report candidate can be produced
- keep all output flags false
- not write Evidence Layer
- not create production cases
- not generate reports, exports, Sandbox fixtures, or public event pages
- output blocked reasons, warning requirements, boundary notes, and recommended next steps

## Boundary Language

Use:

- report generation gate
- report candidate
- boundary block
- reviewed evidence scope
- coverage limitation
- weak evidence warning
- rejected evidence excluded
- duplicate evidence must not amplify risk
- provider output is evidence, not truth
- not official verification
- not full-web coverage
- audit trace
- future report runtime

Avoid:

- report generated
- report-ready by default
- official verified
- full-web coverage
- all-platform coverage
- complete public opinion
- causal proof
- production evidence merged
- PDF ready
- deck ready
- public event ready
