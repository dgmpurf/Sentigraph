# Analysis Request to Evidence Package Contract v1

Status: architecture contract draft

Scope: file-based MVP contract between Sentigraph and evidence providers

This document defines how Sentigraph can request evidence from an external provider and how the provider can return an Evidence Export v1 package. It is documentation only. It does not implement backend routes, provider HTTP APIs, job runners, collectors, or platform integrations.

## Overview

Sentigraph is provider-agnostic. It should communicate with providers through explicit request and response artifacts rather than provider-specific runtime code.

The contract has three parts:

1. Sentigraph writes an analysis request.
2. Provider returns a job result and an Evidence Export v1 package.
3. Sentigraph decides whether the package is visible, valid, reviewable, importable, or rejected.

## Part A: Analysis Request

JSON-like shape:

```json
{
  "schema": "sentigraph_analysis_request_v1",
  "request_id": "req_20260618_example",
  "created_at": "2026-06-18T00:00:00Z",
  "created_by": "sentigraph_local_user",
  "case_seed": {
    "title": "Example public event",
    "description": "Short event description.",
    "keywords": ["keyword1", "keyword2"],
    "negative_keywords": ["unrelated keyword"],
    "language": ["zh-CN"],
    "event_type": "public_opinion_event",
    "sensitive_flags": []
  },
  "sampling_plan": {
    "platforms": ["youtube", "reddit", "news_site"],
    "time_range": {
      "start": "2026-06-01T00:00:00Z",
      "end": "2026-06-18T00:00:00Z"
    },
    "target_comment_count": 500,
    "target_source_count": 30,
    "max_runtime_minutes": 60,
    "sample_strategy": "stratified_public_sample"
  },
  "safety_policy": {
    "allow_live_collection": false,
    "allow_saved_profile": false,
    "allow_manual_snapshot": true,
    "allow_official_api": true,
    "allow_vendor_api": true,
    "forbid_proxy_pool": true,
    "forbid_captcha_bypass": true,
    "forbid_private_content": true
  },
  "privacy_policy": {
    "remove_raw_author_id": true,
    "remove_raw_author_name": true,
    "remove_profile_url": true,
    "remove_private_messages": true,
    "minor_sensitive_mode": true
  },
  "output": {
    "package_schema": "sentigraph_evidence_export_v1",
    "package_slug": "example-public-event-20260618",
    "package_index_required": true
  }
}
```

### Request Fields

| Field | Meaning |
| --- | --- |
| `schema` | Contract schema name. Use `sentigraph_analysis_request_v1` for this version. |
| `request_id` | Stable request identifier generated by Sentigraph. Used for idempotency and result matching. |
| `created_at` | ISO timestamp when Sentigraph created the request. |
| `created_by` | Non-secret label for the request creator or local operator. Do not include personal credentials. |
| `case_seed.title` | Human-readable event or case title. |
| `case_seed.description` | Brief description for provider planning and later case draft creation. |
| `case_seed.keywords` | Positive search and matching terms. |
| `case_seed.negative_keywords` | Terms that help exclude unrelated content. |
| `case_seed.language` | Expected language tags, such as `zh-CN`, `en`, or mixed language lists. |
| `case_seed.event_type` | Event category, such as `game_community_event`, `brand_risk_event`, or `public_opinion_event`. |
| `case_seed.sensitive_flags` | Flags that require extra care, such as minor-sensitive contexts. |
| `sampling_plan.platforms` | Requested platforms or source categories. Provider may skip unsafe or unsupported sources. |
| `sampling_plan.time_range` | Target event window. Provider should report actual coverage in the package. |
| `sampling_plan.target_comment_count` | Requested comment sample size, not a guarantee. |
| `sampling_plan.target_source_count` | Requested parent source/root item count, not a guarantee. |
| `sampling_plan.max_runtime_minutes` | Maximum provider runtime budget. |
| `sampling_plan.sample_strategy` | Sampling approach, for example `stratified_public_sample`. |
| `safety_policy.allow_live_collection` | Whether live collection is allowed by this request. Default should be false unless explicitly enabled. |
| `safety_policy.allow_saved_profile` | Whether saved profiles are allowed. Sentigraph should not store those profiles. |
| `safety_policy.allow_manual_snapshot` | Whether manually exported local snapshots are allowed. |
| `safety_policy.allow_official_api` | Whether approved official APIs may be used. |
| `safety_policy.allow_vendor_api` | Whether contracted vendor APIs may be used. |
| `safety_policy.forbid_proxy_pool` | Proxy pool or evasion must remain forbidden. |
| `safety_policy.forbid_captcha_bypass` | Captcha bypass must remain forbidden. |
| `safety_policy.forbid_private_content` | Private content must be excluded. |
| `privacy_policy.remove_raw_author_id` | Provider should remove raw author identifiers from export. |
| `privacy_policy.remove_raw_author_name` | Provider should remove raw author names from export. |
| `privacy_policy.remove_profile_url` | Provider should remove profile URLs from export. |
| `privacy_policy.remove_private_messages` | Provider should exclude private messages from export. |
| `privacy_policy.minor_sensitive_mode` | Provider should use stricter treatment for minor-sensitive events. |
| `output.package_schema` | Expected package schema. |
| `output.package_slug` | Desired package folder/name slug. |
| `output.package_index_required` | Whether provider must refresh a discoverable package index. |

## Part B: Provider Response / Job Result

JSON-like shape:

```json
{
  "schema": "sentigraph_provider_job_result_v1",
  "request_id": "req_20260618_example",
  "provider_job_id": "provider_job_001",
  "provider_type": "private_collector",
  "status": "package_ready",
  "safety_status": "safe",
  "package_path": "exports/sentigraph-evidence-v1/example-public-event-20260618",
  "package_name": "example-public-event-20260618",
  "package_role": "selected_public_sample",
  "package_index_path": "exports/sentigraph-evidence-v1/package_index.json",
  "counts": {
    "evidence": 0,
    "comments": 0,
    "sources": 0,
    "roots": 0
  },
  "validation": {
    "status": "passed",
    "errors": 0,
    "warnings": 0
  },
  "coverage": {
    "coverage_level": "selected_public_sample",
    "not_full_web": true,
    "not_full_platform": true,
    "not_full_thread": true
  },
  "privacy": {
    "raw_author_ids_removed": true,
    "raw_author_names_removed": true,
    "profile_urls_removed": true,
    "private_messages_excluded": true
  },
  "skipped": [],
  "notes": []
}
```

### Provider Response Fields

| Field | Meaning |
| --- | --- |
| `schema` | Provider job result schema name. Use `sentigraph_provider_job_result_v1`. |
| `request_id` | Must match the Sentigraph request. |
| `provider_job_id` | Provider-side job identifier. Should not expose account secrets. |
| `provider_type` | One of the supported provider types, such as `private_collector` or `vendor_api_provider`. |
| `status` | Provider job state, such as `package_ready`, `validation_warn`, or `blocked_by_safety_gate`. |
| `safety_status` | Safety gate state: `safe`, `hold`, `cooldown`, or `blocked`. |
| `package_path` | Local or future provider path to the Evidence Export v1 package. |
| `package_name` | Package folder or display name. |
| `package_role` | Intended use, such as `selected_public_sample`, `local_snapshot`, or `vendor_sample`. |
| `package_index_path` | Path to provider package index if available. |
| `counts.evidence` | Total normalized evidence item count. |
| `counts.comments` | Comment or reply evidence count. |
| `counts.sources` | Source count. |
| `counts.roots` | Root/parent content count. |
| `validation.status` | Structural validation state: `passed`, `warn`, or `failed`. |
| `validation.errors` | Number of validation errors. |
| `validation.warnings` | Number of validation warnings. |
| `coverage.coverage_level` | Coverage category, such as `selected_public_sample`. |
| `coverage.not_full_web` | Must be true unless the provider has documented full-web coverage, which current Sentigraph does not claim. |
| `coverage.not_full_platform` | Must be true unless official platform-wide access is documented. |
| `coverage.not_full_thread` | Must be true unless full-thread coverage is documented. |
| `privacy.raw_author_ids_removed` | Whether raw author IDs were removed. |
| `privacy.raw_author_names_removed` | Whether raw author names were removed. |
| `privacy.profile_urls_removed` | Whether profile URLs were removed. |
| `privacy.private_messages_excluded` | Whether private messages were excluded. |
| `skipped` | Provider-side skipped sources or skipped platforms with reasons. |
| `notes` | Human-readable notes, warnings, or operator caveats. |

## Part C: Sentigraph Ingestion Decision

Sentigraph should not import every provider result automatically. It should make an explicit ingestion decision.

| State | Meaning |
| --- | --- |
| `visible_in_external_bridge` | Package metadata can be shown in the local External Collector Bridge. |
| `ready_for_validation` | Package exists and can be validated locally. |
| `validation_failed` | Package cannot be imported because structural validation failed. |
| `ready_for_case_draft` | Package passed validation and can seed a case draft. |
| `requires_human_review` | Package is structurally usable but needs human review due to warnings, coverage, trust, privacy, or provenance issues. |
| `ready_for_frontend_fixture` | Package can be transformed into a frontend-only fixture for demo/prototype use. |
| `ready_for_demo_integration` | Package is ready for an explicitly labeled demo flow. |
| `rejected_for_privacy` | Package must not be imported because privacy requirements failed. |
| `rejected_for_coverage` | Package must not be used for the intended claim because coverage is too limited or misleading. |

## Part D: Versioning and Idempotency

Recommended fields:

| Field | Purpose |
| --- | --- |
| `request_id` | Sentigraph-generated request ID. |
| `provider_job_id` | Provider-generated job ID. |
| `idempotency_key` | Stable key to prevent duplicate provider work or duplicate ingestion. |
| `package_hash` | Hash of package content or manifest-declared package hash. |
| `manifest_hash` | Hash of `manifest.json`. |
| `generated_at` | Provider package generation timestamp. |
| `schema_version` | Evidence package schema version. |
| `provider_contract_version` | Provider contract version used to generate the result. |

Idempotency principles:

- Same request plus same idempotency key should not create duplicate case evidence.
- Same package hash should not be imported twice as separate evidence without explicit duplicate handling.
- Revalidation should be repeatable without mutating package contents.

## Part E: File-Based MVP

Phase 1 is local file exchange.

Recommended flow:

```text
Sentigraph writes:
  job_requests/<request_id>.json

Provider writes:
  job_results/<request_id>.json

Provider writes Evidence package under:
  <external_exports_dir>/<package_name>/

Provider refreshes:
  package_index.json

Sentigraph reads:
  package_index.json
  Evidence Export v1 package
  validation_report.json
```

File-based MVP constraints:

- Sentigraph does not run provider collection jobs.
- Sentigraph does not store provider credentials.
- Sentigraph does not fetch source URLs.
- Sentigraph validates local package files only.
- Sentigraph imports only normalized evidence and safe metadata.

## Part F: Future HTTP API

Future provider HTTP endpoints may be considered after security and product gates.

Possible future endpoints:

```text
POST /provider/jobs
GET /provider/jobs/{id}
GET /provider/packages
GET /provider/packages/{name}
POST /provider/jobs/{id}/cancel
```

These endpoints are planning notes only. They are not implemented by this document.

Future HTTP API requirements:

- authenticated provider boundary,
- no secret display in Sentigraph UI,
- explicit cancellation semantics,
- safe retry and idempotency,
- provider-side safety gates,
- immutable package artifacts or auditable package revisions,
- privacy and coverage metadata required before import.

## Current Non-Implementation Statement

This contract does not implement:

- backend API routes,
- provider APIs,
- provider job runners,
- crawler execution,
- collector integration,
- browser automation,
- URL fetching,
- live platform data collection,
- report export,
- or automated truth verification.
