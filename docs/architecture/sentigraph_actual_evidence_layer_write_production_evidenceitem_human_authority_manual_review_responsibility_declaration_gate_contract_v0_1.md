# Sentigraph Actual Evidence Layer Write / Production EvidenceItem Human Authority / Manual Review Responsibility Declaration Gate Contract v0.1

## A. Contract Purpose

This contract defines the 9A-8 governance boundary. It turns the inactive 9A-8 discussion from 9A-7 into a docs-only declaration-gate design and preserves the separation before any actual Evidence Layer write or production EvidenceItem creation.

This contract is docs-only. It does not implement backend code, tests, frontend behavior, routes, APIs, runtime persistence, helper execution, Evidence Layer write, production EvidenceItem creation, Review Queue runtime, production case creation, production analysis_run creation, actual analysis execution, production Analysis Result creation, Source 11 runtime, FinalSummaryReport runtime, public/export/final-delivery runtime, provider/collector jobs, or Project Source files.

## B. Accepted 9A-7 Completion Meaning

9A-7 is accepted under this narrow interpretation:

- actual-write readiness gate discussion completed for declaration purposes
- human_authority_declaration_gate_discussion_ready = yes
- actual write remains not ready
- production EvidenceItem creation remains not ready
- human authority remains not validated
- manual review responsibility remains not accepted by a human in an audit-visible way
- final write authorization remains absent
- write-permitting authorization object remains absent
- 8W-69 pause remains preserved
- Source 11 / FinalSummaryReport remain separate
- review console remains no-write

9A-7 completion does not approve actual write. It does not approve production EvidenceItem creation. It does not validate authority. It does not accept responsibility. It does not create a write authorization object that permits write.

The only forward movement allowed by this contract is discussion of a future tests-only declaration safety contract gate.

## D. Codex Authority Boundary

Codex cannot fabricate human authority.

Codex cannot accept manual review responsibility on behalf of the user.

Codex cannot convert a docs-only declaration into write authorization.

Codex cannot declare production write permission for the user.

Any actual authority or responsibility declaration must come from an explicit human outside Codex.

This phase must use safe labels only and must not include real person PII.

## I. Future Tests-only Gate Rule

The future 9A-9 gate, if separately approved, may test declaration safety only.

It may verify the declaration schema, Codex authority boundary, safe labels, forbidden fields, no-write false flags, and route/API/frontend separation.

It must not validate authority in a runtime sense. It must not accept responsibility. It must not perform final write authorization. It must not create or run any write-authorizing object.

## J. Actual Write Separation

Actual Evidence Layer write remains separated from 9A-8 and any future 9A-9 tests-only phase.

A later actual-write phase would require:

- a new exact approval phrase
- explicit human authority provided by a human outside Codex
- a human acceptance step for manual review responsibility
- acknowledged warning_count
- acknowledged human_review_required
- acknowledged no_automatic_trust_upgrade
- blockers cleared or explicitly paused
- risks classified
- input lineage verified
- raw/private/secret absence confirmed
- audit/rollback/revocation plan
- final write authorization explicitly performed
- stop before write if any blocker remains
