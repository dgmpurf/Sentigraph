# B-End Review Quick Start

Status: professional review guidance only. This document does not implement B-end report runtime or external delivery.

## Goal

Check whether professional reviewers understand Sentigraph's business value, evidence boundaries, and report structure without overclaiming platform coverage, verification, or predictive certainty.

## Route Flow

1. `/#/public-events/donglu-sunjihai-youth-football`
2. `/#/opinion-ecosystem?sample=donglu-sunjihai-youth-football`
3. `/#/reports/donglu-sunjihai-youth-football-sample`
4. Optional technical explanation: `/#/analysis-requests`

## Suggested Framing

Use this opening:

> 这是一套本地演示，用来展示公共事件样本如何被整理成事件页、生态沙盒和报告样例。它不是全网抓取、不是实时平台监控、不是官方验证，也不执行真实平台动作。

## Page Prompts

### Dong/Sun Event Detail

Ask:

- Does the event detail page provide enough context for a professional review?
- Is the evidence coverage explanation credible?
- Which wording feels too strong or underexplained?

### Sandbox V2

Ask:

- Does the T0-T6 historical replay help explain the event lifecycle?
- Is ResponseTempo useful for PR / operations timing?
- Does the reviewer understand that this is historical replay, not future prediction?
- Are PeopleCluster and InfluenceCore visually and conceptually clear?

### B-End Report Sample

Ask:

- Does the report sample show business value?
- Is the response tempo / risk opportunity / suggested action structure useful?
- Which section feels sellable?
- Which section feels confusing?
- Which section feels overclaimed?
- Would this help PR, MCN, sports, brand, public-facing, or community operations work?

### Optional Governance Explanation

Use `/#/analysis-requests` only if the reviewer is technical or asks how evidence moves through governance.

Clarify:

- Local Exchange Reader is disabled-by-default metadata-only scaffold.
- It is not private collector integration.
- Provider output is evidence, not truth.
- Gates are designed to prevent accidental promotion, delivery, or report generation.

## B-End Questions

- Does the report sample show business value?
- Is the evidence coverage explanation credible?
- Is the response tempo / risk opportunity / suggested action structure useful?
- Are boundaries clear enough for PR / MCN / sports / public-facing clients?
- Which section feels sellable?
- Which section feels confusing or overclaimed?
- What would they need before paying for or piloting this?

## Red Flags

- Reviewer thinks the system has full-web coverage.
- Reviewer thinks the sample is officially verified.
- Reviewer thinks Sandbox output is causal proof.
- Reviewer thinks report suggestions execute real platform actions.
- Reviewer asks for scraping, anti-bot bypass, cookie crawling, or hidden APIs as production path.

Do not promise those capabilities.
