## 4. C-End Value Signal Checklist

Positive signals:

- [ ] Wants to open another event.
- [ ] Wants to share an event page.
- [ ] Understands event summary quickly.
- [ ] Finds Sandbox V2 helpful for event understanding.
- [ ] Understands selected sample limitation and still finds value.
- [ ] Uses the request/vote mock without assuming it is real heat.
- [ ] Asks for clearer event categories, not live scraping.

Weak signals:

- [ ] Leaves after event list.
- [ ] Cannot explain what the product does.
- [ ] Treats it as a news site only.
- [ ] Treats it as a game-like visualization only.
- [ ] Ignores all boundary copy.
- [ ] Thinks sample limitation invalidates all value.

## 5. B-End Value Signal Checklist

Positive signals:

- [ ] Names a concrete professional use case.
- [ ] Asks for evidence coverage or provenance.
- [ ] Asks for report export or briefing format.
- [ ] Notices human review / audit importance.
- [ ] Understands fixed report sample vs production report runtime.
- [ ] Asks about compliance and source permissions.
- [ ] Wants a POC or another industry event.

Weak signals:

- [ ] Cannot identify decision-support value.
- [ ] Wants raw full comment dump as default.
- [ ] Treats the report as official truth.
- [ ] Treats sandbox output as forecast guarantee.
- [ ] Wants automatic public actions or covert influence.
- [ ] Rejects boundary language as unclear or too hidden.
