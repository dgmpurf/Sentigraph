# Opinion Ecosystem 8S-14 Trusted Playtest Entry Criteria v0.1

## A. Purpose

This document defines when trusted playtest may begin.

No playtest is executed in this phase.

## B. Entry Criteria

Trusted playtest may begin only after:

- internal recording capture reviewed
- route freeze accepted
- generated run works
- no visible UI/runtime errors
- boundary wording visible
- no secrets/private paths/raw identifiers visible
- no generated response text
- no publish/send/post/execute CTA
- playtest script prepared
- observer note template prepared
- feedback triage template prepared

## C. Allowed Trusted Playtest Scope

Allowed:

- 1 to 3 trusted people
- local screen-share or supervised local demo
- no public posting
- no public link
- no mass user test
- no analytics
- no account creation
- no payment/sponsor flow

## D. Blocked Scope

Blocked:

- public beta
- external mass testing
- production deployment
- real API/LLM
- collector run
- private collector integration
- real package row parsing
- Evidence Layer write
- production case / analysis_run
- generated public response
- publish/send/post/execute
- target_user_list / persuasion_score / truth_score / official_verified / prediction_probability
- psychological_profile / personality_diagnosis

## E. Playtest Success Criteria

Success means:

- user understands selected sample boundary
- user understands not full-web/full-platform
- user understands PeopleCluster is anonymous aggregate proxy
- user understands generated run is local fixture output
- user can follow Dong/Sun route without getting lost
- user can tell what B-end report sample represents
- user does not think the system is live crawling or officially verifying facts
