# 数据授权与证据提交说明

适用产品：归墟舆情分析 / Sentigraph

本说明用于官网、产品页、上传入口、平台审核材料和企业客户培训。它解释用户可以提交哪些数据、需要承担哪些确认义务，以及系统如何处理未验证证据。

## 1. 可以提交的数据

用户可以在有合法来源和使用权的前提下提交以下数据：

- 公开文章、新闻、帖子、视频说明或评论的 URL、标题、正文、摘要；
- 公开评论、回复、用户反馈或投诉文本；
- 与事件相关的互动指标，如点赞、回复、分享、浏览量；
- 企业合法取得的 CSV/Excel 样本；
- 第三方供应商在 POC 中提供且不含密钥的样本文件；
- 经过平台官方授权或 OAuth 授权后可处理的数据；
- 本地演示和测试用 mock 数据。

## 2. 不应提交的数据

用户不得提交：

- 未经授权的个人信息或敏感个人信息；
- 私信、私密群组、非公开账号内容；
- 登录态数据、Cookie、Token、账号密码、client secret、API Key；
- 付费墙、会员区、未授权下载或受限内容；
- 通过验证码绕过、反爬绕过、代理规避、隐藏接口或 Cookie 抓取得到的数据；
- 与舆情分析目的无关的个人资料、身份号码、精确位置、财务账号等信息。

## 3. 用户授权确认

提交数据前，用户应确认：

> 我确认对所提交的公开舆情证据拥有合法来源或使用权，并同意将其用于归墟舆情分析 / Sentigraph 的证据归一化、风险分析、报告生成和人工复核。

如果用户未完成授权确认，系统可继续保存必要的规范化证据，但会降低信任标签并标记为 `needs_review` 或 `user_attestation_missing`。

## 4. 证据复核原则

Sentigraph 不会将用户提交内容自动视为真实、完整或已验证。系统会根据来源和字段为证据设置：

- 来源类型；
- 采集方式；
- 验证状态；
- 信任标签；
- 来源 URL 状态；
- 用户授权状态；
- 风险标记；
- 重复组和重复次数。

低信任、未验证、截图转录、缺少来源、缺少授权确认、重复提交或包含风险标记的证据会进入人工复核队列。

## 5. 截图和转录说明

截图、截图转录、人工复制文本和外部工具辅助整理文本不会被系统自动验证。它们应默认视为未验证证据，只有在人工复核并结合可信来源后，才能提高使用信心。

系统不会使用 AI 自动判断截图真实性，也不会把截图内容称为平台官方验证数据。

## 6. 驳回证据的处理

人工复核中被驳回的证据默认不进入后续分析、代表性评论和报告正文。被驳回证据仍可保留在案例中用于审计，便于追溯提交原因、复核原因和处理过程。

## 7. 重复证据的处理

系统会对同一案例中的相同文本或相同 URL 进行去重。重复提交可作为“重复出现”的信号保留，但不会直接重复放大情绪、话题或风险计数。

## 8. 供应商数据说明

供应商样本应标记为 `acquisition_mode=data_vendor`。只有当供应商提供书面来源、授权和许可说明时，才能标记为 `verification_status=vendor_attested`。

`vendor_attested` 表示供应商对来源或授权作出说明，不表示平台官方已验证内容，也不表示证据本身一定真实。供应商数据仍需经过字段完整性、重复率、来源可追溯性、删除同步、个人信息处理和合同权利复核。

## 9. 平台官方数据说明

经官方 API 或 OAuth 授权获取的数据可具有更高的来源可信度，但仍不代表评论或帖子中的每一项事实陈述为真。平台官方数据应在授权范围、接口规则、配额限制和平台政策下使用。

当前抖音、Bilibili、小红书、微博等真实接口仍需官方权限确认后才能启用。未获授权前，不应通过抓取、Cookie、验证码绕过或反爬绕过方式替代官方接口。
